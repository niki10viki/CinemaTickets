# Класова модель CinemaTickets

Варіант 9 — продаж квитків у кінотеатрі. Документ — замовлення квитків `TicketOrder`,
позиція — квиток на конкретне місце `TicketLine`, довідник учасників — глядач `Viewer`,
довідник об'єктів обліку — кіносеанс `Screening`.

## Сутності

| Сутність | Роль | Незмінний | Інваріант |
| --- | --- | --- | --- |
| TicketLine | позиція документа: одне місце на сеансі | так, record | ScreeningId > 0, Row > 0, Seat > 0, Price >= 0, 0 <= Discount <= Price |
| TicketOrder | документ зі станом | ні, агрегат | Id > 0, ViewerId > 0; квитки додаються лише у стані New; одне місце (сеанс, ряд, місце) не повторюється |
| Viewer | довідник учасників | так, record | Id > 0, Name не порожнє, Email містить @ |
| Screening | довідник об'єктів обліку | так, record | Id > 0, MovieTitle і Hall не порожні, BasePrice > 0, SeatsTotal > 0 |

Позиція й учасник не мають життєвого циклу: зміна ціни чи пошти — це новий об'єкт, тому
вони незмінні. Сеанс у розкладі теж не редагується: перенесення означає новий сеанс.
Замовлення проходить стани, тож це змінний агрегат, який змінюється лише методами-переходами.

## Стани замовлення

| Зі стану | До стану | Метод | Умова |
| --- | --- | --- | --- |
| New | Paid | Pay | є хоча б один квиток |
| New | Cancelled | Cancel | завжди |
| Paid | Used | MarkUsed | завжди (квитки погашено на вході в залу) |
| Paid | Refunded | Refund | щонайменше за 1 годину до початку сеансу |

Інші переходи заборонені: зі станів Used, Cancelled і Refunded вийти не можна.
