\# Стандарт кодування проєкту CinemaTickets



\## 1. Загальні положення

Цей документ визначає стандарти написання, форматування та оформлення коду для навчального проєкту з дисципліни «Конструювання програмного забезпечення».



\## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |

| :--- | :--- | :--- | :--- |

| Клас, запис | PascalCase, іменник | `TicketLine` | `ticketline` |

| Інтерфейс | I + PascalCase | `ITicketRepository` | `Repository` |

| Метод | PascalCase, дієслово | `CalculateTotal` | `calc` |

| Властивість | PascalCase, іменник | `SeatsTotal` | `GetSeatsTotal` |

| Приватне поле | \_ + camelCase | `\_lines` | `m\_Lines` |

| Локальна змінна | camelCase | `totalAmount` | `ta` |

| Константа | PascalCase | `MaxSeatsPerOrder` | `MAX\_SEATS` |

| Перелічення | PascalCase, однина | `TicketStatus` | `TicketStatuses` |



\## 3. Форматування

1\. Відступ — 4 пробіли; табуляція заборонена\[cite: 19].

2\. Довжина рядка — не більше ніж 100 символів\[cite: 19].

3\. Фігурні дужки — стиль Allman, обов'язкові навіть для однієї інструкції в тілі `if`\[cite: 19].

4\. Між членами класу — рівно один порожній рядок\[cite: 19].

5\. Директиви `using` на початку файлу, системні перші, невживані видаляються\[cite: 19].

6\. Простір імен — файлового рівня (`namespace X;`)\[cite: 19].



\## 4. Коментарі та документація

Коментарі мають пояснювати причину прийняття рішення («чому»), а не дублювати код («що»). Для публічних членів бібліотеки використовується XML-документація.



\## 5. Структура проєкту

Рішення розділене на два проєкти: `CinemaTickets.Core` (чиста бізнес-логіка) та `CinemaTickets.App` (консольний шар введення-виведення).



\## 6. Правила комітів

Використовується конвенція Conventional Commits: `feat`, `fix`, `docs`, `chore`, `style`. Повідомлення пишуться в наказовому способі.
